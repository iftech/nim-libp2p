### contradicts-spec (proven violation, first pass only)

#### Finding 1 (F-e89a894e) — maintainRegistrations re-selects a registrar that replied Rejected and re-sends the same advert — **unconfirmed**, medium severity, high confidence

The specification says: "If the `status` is `Rejected`, the advertiser ... SHOULD NOT attempt further registrations with this registrar for this advertisement." On Rejected, `advertiseToRegistrar` only returns and nothing records the rejection. The next `maintainRegistrations` pass sees the bucket below `K_register`, treats the rejected registrar as an ordinary candidate (only registrars with a running task are excluded) and starts a new task with the same advertisement bytes and no ticket. A rejecting registrar is re-sent the same advert on maintenance passes for as long as the service is provided.

What this does not establish: the clause is a SHOULD NOT, so this is a divergence from a recommendation rather than a hard prohibition. The companion MUST ("remove the registrar from the ongoing registrations for that bucket") is met. Re-selection is certain only when the bucket holds at most `K_register` peers; in larger buckets it is a random draw each round.

- Locations: `libp2p/protocols/service_discovery/advertiser.nim:370-372` (Rejected branch returns, records nothing); `libp2p/protocols/service_discovery/advertiser.nim:209-220` (candidates exclude only active registrars and self; new task started with `advert.bytes`).
- Repro: `export PATH=/w/cache/nim-2.2.14/bin:$PATH; make test test_20261122T235204_5620dd_1; rc=$?; git ls-files --error-unmatch tests/.gitignore >/dev/null 2>&1 || rm -f tests/.gitignore; exit $rc` (expect: nonzero) → observed by the first pass: `test_20261122T235204_5620dd_1.nim(111, 52): Check failed: rejecting.dialed.countIt(it == registrar) == 1`, `[FAILED ] a registrar that replied Rejected gets no further REGISTER for the same advertisement`.
- Second pass: no verdict recorded.
- Fix: remember, per provided service, the registrars that rejected the current advertisement; add to it in the Rejected branch (`advertiser.nim:370`), exclude it when building candidates in `maintainRegistrations` (`advertiser.nim:209-214`) and in `scheduleRegistrations` (`advertiser.nim:408`), and clear it when the advertisement bytes change or the service is removed.

### missing-requirement (missing capability, first pass only)

#### Finding 2 (F-11b5c5ba) — REGISTER reply is awaited with no timeout, so a silent registrar keeps its K_register slot — **unconfirmed**, medium severity, medium confidence

The specification's Error Handling table says: "Timeout | Close stream, retry with exponential backoff". The advertiser sends REGISTER and awaits the reply with no deadline: `advertiseToRegistrar` awaits `sendRegister`, which awaits the connection send, and none bounds the wait. A registrar that accepts the stream and never answers keeps the attempt pending, the stream open and one of the bucket's `K_register` slots occupied; `maintainRegistrations` counts the task as active and does not replace it. The discoverer's GET_ADS path does apply `config.timeout`.

What this does not establish: the spec row names no timeout value, so the test measures against `KadDHTConfig.timeout` (25 times over). The test uses a stub stream, so it does not show whether a real muxed stream's own idle timeout, outside the unit, would eventually end the hang; the wait is unbounded in the unit, not necessarily in a deployment. Failures that surface as errors (dial, read or write failure) do end the task and feed the existing exponential dial backoff.

- Locations: `libp2p/protocols/service_discovery/advertiser.nim:326-330` (await of `sendRegister` with no deadline); `libp2p/protocols/service_discovery/advertiser.nim:278-282` (await of `disco.send` with no deadline).
- Repro: `export PATH=/w/cache/nim-2.2.14/bin:$PATH; make test test_20261122T235204_5620dd_2; rc=$?; git ls-files --error-unmatch tests/.gitignore >/dev/null 2>&1 || rm -f tests/.gitignore; exit $rc` (expect: nonzero) → observed by the first pass: `test_20261122T235204_5620dd_2.nim(64, 23): Check failed: stream.closed()` and `test_20261122T235204_5620dd_2.nim(66, 27): Check failed: task.fut.finished()`, `[FAILED ] a REGISTER whose registrar never answers times out and frees its slot`.
- Second pass: no verdict recorded.
- Fix: wrap the `sendRegister` await in `advertiseToRegistrar` (`advertiser.nim:326`) with `disco.config.timeout`, cancel the send on expiry so the stream is reset, record the expiry as a dial failure so the exponential backoff applies, and end the task so the slot can be refilled.
